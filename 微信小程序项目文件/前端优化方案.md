# 格至学习系统小程序端前端优化方案

## 1. 文档目标

当前小程序已经具备登录、首页、AI 导师、学术空间、错题本、知识库、个人中心等核心页面，但整体前端仍处在“功能雏形”阶段。主要问题集中在：

- UI 图标大量依赖 emoji，正式感和一致性不足。
- 信息层级不够清晰，页面阅读负担偏重。
- 组件样式分散，卡片、按钮、标签、弹窗、输入区缺少统一规范。
- 新中式/书院风已有基础，但还没有形成完整设计系统。
- 学习系统的核心价值，如学情画像、AI 辅导、错题成长、知识库检索，没有被足够视觉化。

本方案目标是在不等待后端完全完善的前提下，先完成小程序端的视觉体系、组件体系和页面可读性升级，让产品从“可用 demo”提升为“可展示、可迭代、可发布预备”的学生端学习系统。

## 2. 优化总方向：书院升级

本次前端优化采用“书院升级”方向：保留格至学习系统已有的新中式、书院、格物致知气质，但避免停留在米色背景、红色点缀和 emoji 图标的浅层表达。

### 2.1 设计关键词

- 新中式学习空间
- 清晰的学习任务流
- 温润但不老旧
- 有 AI 产品的轻科技感
- 学情数据可视化
- 移动端高可读性

### 2.2 设计原则

1. 先解决可读性，再做装饰。
2. 所有图标、颜色、卡片和动效都服务于学习任务。
3. 书院风不等于复古堆砌，要用现代移动端布局表达传统气质。
4. AI 能力要被看见，但不要做成泛科技风。
5. 每个页面只保留一个视觉重点，避免满屏元素互相抢注意力。

## 3. 当前问题诊断

### 3.1 图标问题

当前底部 Tab、首页入口、聊天头像、知识库入口等位置大量使用 emoji。问题包括：

- 不同系统渲染不一致，真机效果不可控。
- emoji 风格与书院风不统一。
- 表情化较强，削弱教育产品的专业感。
- 无法形成品牌识别。

解决策略：

- 建立一套统一线性图标或仿印章图标系统。
- TabBar 使用固定尺寸 PNG 或 SVG 转小程序可用资源。
- 功能入口图标分为 4 类：学习、AI、错题、知识库。
- AI 智能体头像不再使用 emoji，而是使用角色化徽章。

建议图标风格：

- 线条圆角：2rpx-3rpx。
- 主色：墨黑、印泥红、青黛蓝。
- 辅色：浅米、竹青、金石灰。
- 形态：书页、罗盘、印章、竹简、星轨、笔锋。

### 3.2 可读性问题

当前页面已有内容，但信息密度和视觉层级还不稳定：

- 首页卡片信息较多，但主次关系不够强。
- 聊天页消息气泡可读性可以继续提升，引用区与正文需要更明显区分。
- 论坛列表缺少标题、摘要、作者、互动数据之间的清晰层级。
- 错题本内容复杂，需要用步骤化结构降低理解成本。
- 知识库页面需要更明确地表达“分类 - 文件 - 状态 - 操作”。

解决策略：

- 建立统一字号阶梯。
- 页面标题、模块标题、卡片标题、正文、辅助文字分别定义规范。
- 卡片内部统一采用“标题区 - 内容区 - 行动区”结构。
- 重要指标使用数字视觉化，不再散落在普通文本中。
- 长文本区域增加行高、留白和弱分割。

建议字号体系：

| 类型 | 字号 | 用途 |
| --- | --- | --- |
| 页面主标题 | 42rpx-48rpx | 首页、AI 导师、知识库等页面标题 |
| 模块标题 | 32rpx-36rpx | 学业能力分析、错题诊断、资料分类 |
| 卡片标题 | 28rpx-32rpx | 帖子标题、错题标题、文档标题 |
| 正文 | 26rpx-28rpx | 聊天内容、帖子摘要、诊断正文 |
| 辅助文字 | 22rpx-24rpx | 时间、来源、状态、说明 |
| 数据数字 | 44rpx-72rpx | 掌握度、错题数、研学指数 |

### 3.3 组件不统一问题

目前各页面样式大多独立编写，虽然整体色调接近，但组件标准不足。

需要统一的组件包括：

- 顶部页面头部
- 功能入口宫格
- 数据卡片
- 学习状态标签
- 主按钮/次按钮/危险按钮
- 空状态
- 加载状态
- 弹窗
- 底部输入栏
- 列表卡片
- 分段切换器

解决策略：

- 先在 `app.wxss` 中扩展设计变量和通用类。
- 每个页面只保留页面特有样式，公共样式逐步沉淀。
- 优先统一视觉语言，不急于抽象自定义组件，避免一次性改动过大。
- 第二阶段再将高频 UI 抽成 `components`。

### 3.4 品牌感不足问题

“格至学习系统”的名称和“格物致知”气质很强，但当前页面没有充分转化成视觉记忆点。

解决策略：

- 建立品牌符号：“格纹纸脉 + 印章红点 + 竹简分隔线”。
- 首页学情卡改成“学业案卷”概念。
- AI 导师页改成“问学席”概念。
- 知识库改成“藏书阁/资料阁”概念，但按钮文案仍保持现代清晰。
- 错题本改成“错因修正簿”，突出诊断、练习、掌握闭环。

## 4. 视觉设计系统规划

### 4.1 色彩系统

当前已有米白、印泥红、墨黑等变量，可进一步扩展为完整 token。

建议色彩：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-paper` | `#F6F1E7` | 页面背景 |
| `--color-card` | `#FFFDF8` | 卡片背景 |
| `--color-ink` | `#28231F` | 主文字 |
| `--color-ash` | `#7B7168` | 辅助文字 |
| `--color-seal` | `#8B2520` | 品牌强调色 |
| `--color-seal-soft` | `#F1D8D2` | 红色浅底标签 |
| `--color-indigo` | `#253E5C` | AI、知识库、深色辅助 |
| `--color-bamboo` | `#4F6F52` | 成长、掌握、完成状态 |
| `--color-border` | `#E7DDC8` | 边框和分割线 |
| `--color-warning` | `#B7791F` | 警示、待完成 |

调整策略：

- 页面背景保持温润纸色。
- 卡片背景比页面更亮，增强层次。
- 红色只用于关键动作和品牌标记，避免满屏红。
- AI 相关区域加入青黛蓝，形成“传统 + 智能”的区分。
- 成功/掌握状态用竹青，不用普通绿色。

### 4.2 字体与排版

微信小程序字体受系统限制，不能完全依赖外部字体，因此重点优化字重、字号、行高和层级。

建议策略：

- 标题继续使用宋体类衬线字体，增强书院气质。
- 正文使用系统无衬线，保证可读性。
- 数据数字使用更大的字号和紧凑字距。
- 中文正文行高控制在 1.6-1.75。
- 卡片内最多使用 3 个字号，避免视觉噪音。

### 4.3 间距系统

建立 8rpx 基础网格：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--space-1` | `8rpx` | 极小间距 |
| `--space-2` | `16rpx` | 图标与文字间距 |
| `--space-3` | `24rpx` | 卡片内部间距 |
| `--space-4` | `32rpx` | 模块间距 |
| `--space-5` | `48rpx` | 页面大分区 |
| `--space-6` | `64rpx` | 顶部留白、强分隔 |

页面统一左右安全边距建议为 `32rpx`。

### 4.4 圆角与阴影

当前卡片已经有轻阴影，但层次还可以更稳定。

建议：

- 小按钮圆角：16rpx。
- 标签圆角：999rpx。
- 普通卡片圆角：28rpx。
- 重点卡片圆角：36rpx。
- 弹窗圆角：40rpx。
- 阴影只保留一到两档，避免每个页面各自定义。

## 5. 页面级优化策略

### 5.1 启动页与登录页

目标：建立第一眼品牌感，降低 demo 感。

优化策略：

- 启动页加入格至品牌符号，不只是等待跳转。
- 登录页使用“书院门牌”式主视觉：系统名称、简短说明、账号输入区。
- 开发者免登必须弱化为次级入口，避免正式感受损。
- 输入框增加图标、焦点态、错误态。
- 登录按钮使用印章红主按钮，点击后有明确 loading 状态。

步骤：

1. 统一登录页背景和品牌标题。
2. 重做输入框和按钮层级。
3. 隐藏或折叠开发者免登入口。
4. 增加登录错误状态样式。

### 5.2 首页

目标：从“入口集合页”升级为“今日学习仪表盘”。

优化策略：

- 顶部问候区保留，但减少装饰性文字。
- 学情画像卡改成核心视觉焦点，突出掌握度、学习节奏、目标。
- 四个入口图标统一替换，形成品牌入口组。
- 学业能力分析改为更直观的进度条/环形指标。
- 教师提醒弹窗改为更清晰的通知列表。

步骤：

1. 重构首页信息顺序：问候、画像、今日建议、功能入口、能力分析。
2. 将“格物积分”改为可解释指标，如“知识掌握度”。
3. 为 AI 导师、错题特训、课件资料增加行动文案。
4. 空提醒状态增加正向引导。

### 5.3 AI 导师页

目标：提升聊天阅读体验和 AI 能力感。

优化策略：

- Tutor/RAG 切换器视觉升级为分段控制器。
- AI 头像从 emoji 改为角色徽章。
- 用户气泡和 AI 气泡在颜色、宽度、行高上明确区分。
- 引用来源独立成资料卡，避免混在正文中。
- 输入栏固定底部，上传按钮和发送按钮视觉层级清晰。
- 思考状态改为“导师正在整理思路”的轻动效提示。

步骤：

1. 统一消息气泡样式。
2. 重做引用来源卡片。
3. 优化底部输入栏和文件上传入口。
4. 增加空会话建议问题。
5. 为 Tutor/RAG 模式分别设置不同主题色。

### 5.4 学术空间与论坛详情

目标：提高帖子列表扫描效率和详情页阅读体验。

优化策略：

- 分类 Tabs 使用横向胶囊标签，但减少视觉噪音。
- 帖子卡片统一为：分类标签、标题、摘要、作者、互动数据。
- 点赞、回复、浏览等数据使用统一小图标。
- 详情页采用文章式排版，正文行高增加。
- 回复区与正文分层，输入框固定或半固定。

步骤：

1. 替换帖子列表 emoji 和内联样式。
2. 建立论坛卡片组件样式。
3. 详情页正文排版升级。
4. 回复列表增加层级和空状态。
5. 点赞状态增加明确反馈。

### 5.5 错题本

目标：把复杂学习过程拆成可理解的“诊断 - 练习 - 掌握”。

优化策略：

- 顶部统计卡突出总错题、待掌握、已掌握。
- 每道错题卡按结构展示：题目、错因、知识点、操作。
- AI 诊断结果拆为几个固定小节。
- 自测弹窗更像练习卡，而不是普通弹窗。
- 掌握状态使用颜色和图标双重提示。

步骤：

1. 重做错题统计区。
2. 统一错题卡片结构。
3. 优化 AI 诊断展开态。
4. 重做自测弹窗选项样式。
5. 增加错题空状态和学习建议。

### 5.6 知识库

目标：让“资料分类、文件状态、向量化能力”一眼可懂。

优化策略：

- 分类区改成左侧/顶部资料夹式导航。
- 文件卡片显示名称、类型、大小、上传时间、解析状态。
- 上传按钮强调“上传并生成可问答资料”。
- 删除操作降级为更多菜单或轻危险按钮。
- 空分类提示用户上传第一份资料。

步骤：

1. 统一资料夹样式。
2. 重做文件卡片。
3. 增加解析状态视觉标识。
4. 优化新建分类弹窗。
5. 与 AI 导师入口建立联动提示。

### 5.7 个人中心

目标：从“设置页”升级为“学习档案页”。

优化策略：

- 顶部头像区增加身份和学习等级。
- 三个统计指标视觉统一。
- 菜单项替换为正式图标和说明文字。
- 退出登录降级到底部低强调区域。
- 增加学习档案入口，为后续画像详情预留。

步骤：

1. 重做个人信息头部。
2. 统一统计卡片样式。
3. 优化菜单列表可读性。
4. 弱化退出登录。
5. 增加学习档案视觉占位。

### 5.8 底部 TabBar

目标：解决 emoji 图标和选中态不专业问题。

优化策略：

- 替换 emoji 为统一图标资源。
- 选中态使用印章红加浅底托盘。
- 未选中态使用低饱和墨灰。
- 中间 AI 导师可做轻微强调，但不破坏平衡。

步骤：

1. 设计四个 Tab 图标：首页、学术空间、AI 导师、我的。
2. 替换 `custom-tab-bar` 中的 emoji 字符。
3. 优化选中/未选中样式。
4. 适配安全区和不同机型底部高度。

## 6. 组件体系落地步骤

### 阶段一：设计变量与基础样式

目标：先统一视觉底座，不大规模改结构。

任务：

- 扩展 `app.wxss` 的颜色、字号、间距、圆角、阴影变量。
- 增加通用类：页面容器、卡片、标签、按钮、空状态、分割线。
- 清理页面内重复的内联样式。

验收标准：

- 所有页面背景、文字、卡片、按钮风格一致。
- 新增样式变量可以支撑后续页面重构。
- 不影响当前业务逻辑。

### 阶段二：图标与品牌资产替换

目标：去掉主要 emoji 图标，建立正式视觉资产。

任务：

- 设计或引入统一图标资源。
- 替换 TabBar 图标。
- 替换首页四大入口图标。
- 替换聊天智能体头像。
- 替换个人中心菜单图标。

验收标准：

- 首屏不再依赖 emoji 作为主图标。
- 图标尺寸、颜色、描边统一。
- 不同系统真机渲染一致。

### 阶段三：首页与 TabBar 重构

目标：优先优化用户第一印象。

任务：

- 重构首页信息层级。
- 优化学情画像卡。
- 优化功能入口宫格。
- 优化教师提醒弹窗。
- 优化底部 TabBar。

验收标准：

- 首页能清楚回答“我现在学得怎么样、下一步该做什么”。
- TabBar 正式、稳定、有品牌感。
- 页面首屏信息不拥挤。

### 阶段四：AI 导师体验升级

目标：强化产品核心差异化能力。

任务：

- 优化聊天气泡。
- 优化 Tutor/RAG 切换器。
- 优化引用来源卡。
- 优化底部输入栏。
- 增加空会话推荐问题。

验收标准：

- 长回答更易读。
- 引用来源一眼可识别。
- 上传文件和发送消息的操作路径清晰。

### 阶段五：错题本与知识库升级

目标：提升学习闭环页面的结构化表达。

任务：

- 重做错题统计和错题卡。
- 重做 AI 诊断展示。
- 重做自测弹窗。
- 重做知识库分类和文件卡片。
- 增加状态标签和空状态。

验收标准：

- 错题学习路径清晰：看错题、看诊断、做自测、标掌握。
- 知识库路径清晰：建分类、传文件、等待解析、进入问答。

### 阶段六：论坛与个人中心补齐

目标：补齐次核心页面的一致性。

任务：

- 优化论坛列表和详情页阅读体验。
- 优化回复区和互动数据。
- 重做个人中心头部和菜单。
- 统一退出登录、删除等危险操作样式。

验收标准：

- 所有主页面视觉风格统一。
- 操作反馈清晰。
- 论坛和个人中心不再显得像临时页面。

### 阶段七：真机检查与细节打磨

目标：确保设计在微信小程序环境真实可用。

任务：

- 检查 iOS/Android 字体、emoji 替换、图标显示。
- 检查安全区、底部输入栏、TabBar 高度。
- 检查长文本、空数据、接口失败状态。
- 检查弱网 loading 和错误提示。
- 检查包体积和图片资源大小。

验收标准：

- 核心页面在真机上显示稳定。
- 无明显遮挡、溢出、错位。
- 空态、加载态、错误态都有明确提示。

## 7. 页面优先级建议

建议按以下顺序迭代：

1. `app.wxss` 全局设计变量和基础组件类。
2. `custom-tab-bar` 图标和选中态。
3. 首页，因为它决定第一印象。
4. AI 导师页，因为它是产品核心卖点。
5. 错题本和知识库，因为它们构成学习闭环。
6. 登录页和个人中心，补齐品牌完整度。
7. 论坛列表和详情页，提升社区体验。
8. 全量真机检查和细节修正。

## 8. 关键改造清单

- 替换 TabBar 和主要功能入口 emoji 图标。
- 建立全局颜色、字号、间距、圆角、阴影 token。

## 9. 交互与动效策略

动效应少而准，不做满屏动画。

建议动效：

- 首页学情卡进入时轻微上浮。
- TabBar 切换时图标轻微缩放。
- AI 思考状态使用三点节奏动效。
- 错题诊断展开使用高度过渡或淡入。
- 上传文件时显示步骤状态：上传中、解析中、可问答。

不建议：

- 大量粒子背景。
- 高频闪烁。
- 与学习任务无关的装饰动效。
- 过重的 3D 或复杂 Canvas 动效。

## 10. 文案优化策略

当前文案有书院气质，但部分地方偏装饰。后续应做到：

- 标题可以有气质。
- 按钮必须直白。
- 错误提示必须说明问题和下一步。
- 空状态必须给出行动建议。
- AI 模式说明要让学生知道能做什么。

示例：

| 场景 | 当前倾向 | 优化方向 |
| --- | --- | --- |
| RAG 模式 | 已启用专属 RAG 知识库检索 | 已切换到课件问答，可直接询问已上传资料 |
| 空知识库 | 暂无数据 | 上传第一份课件，AI 导师就能基于资料回答问题 |
| 错题掌握 | 标记已掌握 | 已加入掌握记录，画像将同步更新 |
| 网络失败 | 网络连接失败 | 暂时连接不上服务器，请检查网络后重试 |

## 11. 风险控制

前端优化不应一次性大改所有页面逻辑，建议遵守以下原则：

- 第一轮只改样式和静态结构，尽量不碰接口逻辑。
- 图标替换先覆盖主路径，不追求一次性替换所有细节图标。
- 页面重构时保留原数据字段，减少与后端耦合变化。
- 每完成一个页面就进行微信开发者工具预览。
- 避免引入过大的第三方 UI 库，保持原生小程序轻量。

## 12. 最终验收标准

完成本轮前端优化后，应达到以下效果：

- 首屏能明显看出“格至学习系统”的品牌气质。
- 不再有大量 emoji 导致的临时感。
- 首页、AI 导师、错题本、知识库四个核心页面具备清晰信息层级。
- 主要按钮、卡片、标签、弹窗、输入栏风格一致。
- 学情画像、AI 引用、错题诊断、文件解析状态都能被视觉化表达。
- 真机上没有明显溢出、遮挡、错位。
- 后端尚未完善的情况下，前端依然可以作为高质量产品原型展示。
